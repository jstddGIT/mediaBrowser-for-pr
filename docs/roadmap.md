## A. 你已提到的需求

| # | 需求 | 成本 | 标签 | 说明与风险 |
|---|------|------|------|-----------|
| A1 | 视频**静态缩略图**（首帧） | 大 | 需JSX `需新依赖` `原Out-of-Scope` | CEF 无法解码视频帧，方案是 Node + ffmpeg 抽首帧缓存成图片再显示。需引入 ffmpeg（要你同意装）、建缩略图缓存目录与失效策略。 |
| A2 | 视频**悬停擦洗预览**（鼠标位置=不同帧） | 大 | 需JSX `需新依赖` `原Out-of-Scope` | 比 A1 更重：要预抽多帧或实时解码，且 CEF 对 HEVC/ProRes 支持有限，部分素材可能失败。建议排在 A1 之后、优先级最低。 |
| A3 | 素材**拖入时间线** | 中 | 需JSX `原Out-of-Scope` | HTML5 拖拽把媒体路径写入 DataTransfer。坑：CEF 面板→时间线直接落点各版本支持不一，稳妥退化方案是「拖到项目面板/触发导入」。需真机试落点行为。**投入产出比最高，建议作为 v2 首个功能。** |
| A4 | Bin 目录与素材**按名称排序** | 小–中 | 纯前端 | 排序是纯函数，可进 `js/logic.js` 加单测。中文用 `localeCompare`。顺带可做排序方向（升/降）与多排序键（见 S7）。 |
| A5 | 左右面板**大小可拖拽调整** | 小–中 | 纯前端 | 中间加分隔条拖拽改宽度，宽度持久化（见 S6）。 |
| A6 | 面板**美化 + 紧凑布局**（缩小/折叠头部插件名等） | 小 | 纯前端 | CSS + 少量 JS。建议跟随 Premiere 深/浅色主题（CEP 提供宿主主题色）。 |
| A7 | **一键展开所有 Bin** | 中 | 需JSX | 需递归拉取所有层，与 v1「按需加载」相悖——大项目要加进度提示/上限保护，避免卡顿。 |
| A8 | **素材标签**：读取 PR 里用户打的标记，在缩略图下方展示 | 中 | 需JSX `待查证API` | 需核实脚本能读到哪种「标记」：色标签（label/颜色）、说明字段、还是 marker。不同字段可读性不同，下手前先查证并在真机验证。 |
| A9 | **右键菜单** | 中–大 | 需JSX `待查证API` | 见下方拆分。 |
| A9a | └ 在项目中显示（reveal 到项目面板并选中） | 中 | `待查证API` | 需查证 selection / reveal 相关 API 是否可脚本触发。 |
| A9b | └ 标记优质素材 / 评级（快速找回高质量素材） | 中–大 | `待查证API` | **关键提醒**：Premiere 脚本大概率没有可写的原生「评级」字段。可行做法是**自建本地元数据存储**（扩展数据目录下的 json，用 nodeId/媒体路径当键），评级/优质标记存本地，再做筛选。这等于我们自己的一套轻量标记系统，范围比听起来大。 |

## B. 我的补充建议（按价值排序）

| # | 建议 | 成本 | 标签 | 为什么值得 |
|---|------|------|------|-----------|
| S1 | **搜索/过滤框**：按名称过滤当前 Bin（或全项目） | 中 | 纯前端 | 大项目里定位素材最高频的需求，比一层层点快得多。全项目搜索要遍历，可分档。 |
| S2 | **面包屑路径 + 返回上级** | 小 | 纯前端 | 下钻后能一眼看清「我在哪」并快速回退，配合 A3/A7 体验完整。 |
| S3 | **键盘导航**：方向键选中、回车打开、退格返回 | 中 | 纯前端 | 剪辑师手不离键盘，效率提升明显。 |
| S4 | **缩略图尺寸切换 + 网格/列表视图** | 中 | 纯前端 | 大缩略图看画面、列表看名称/信息，适配不同浏览场景。 |
| S5 | **悬停/状态栏显示元数据**：时长、分辨率、帧率、文件大小、路径 | 中 | 需JSX `待查证API` | 不用打开就能判断素材，和 A1/A8 天然协同。部分字段需查证读取方式。 |
| S6 | **记住面板状态**：展开的 Bin、选中项、面板宽度、视图模式 | 小 | 纯前端 | 用 localStorage 持久化。A5/A4/S4 一旦做了，不记住状态会很别扭——建议和它们一起做。 |
| S7 | **按类型/离线筛选** + 更多排序键（类型/时长/导入顺序） | 小–中 | 纯前端 | 和 A4 同一套排序/筛选框架，边际成本低。 |
| S8 | **高亮「当前源监视器中打开」的素材** | 中 | 需JSX `待查证API` | 反向定位：正在看的素材在项目里是哪个。需查证 `getProjectItem`。 |

## C. 建议的推进顺序（快赢优先）

1. **一批纯前端快赢**（A4 排序 + A5 面板可调 + A6 美化/紧凑 + S6 状态持久化 + S2 面包屑）——同一块前端改动，一次做完性价比最高，无新依赖、无真机 API 风险。
2. **A3 拖入时间线**——高价值，单独走一遍需求+真机验证落点。
3. **S1 搜索 + S7 筛选/排序扩展**——在第 1 步框架上扩展。
4. **A7 一键展开、A3 之后的 S3 键盘导航**。
5. **A8 素材标签 / S5 元数据 / A9a 在项目中显示**——同属「读 PR 素材更多信息」，需先集中查证 API 再一起做。
6. **A9b 评级/优质标记**——需先定「本地元数据存储」方案（存哪、用什么当键、如何随项目迁移），范围较大，建议单独立项。
7. **A1 视频缩略图 → A2 悬停预览**——重、需 ffmpeg/受编码限制，放最后；A2 视效果决定是否值得做。
